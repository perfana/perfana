Aggregated SLO — Graph Design Options

When you expand an aggregated SLO row, what should the graph show?

A

Bar chart — scalar value vs threshold

Show the computed value (e.g. p95 = 1 850 ms) as a bar with a red dashed threshold line (2 000 ms). Matches the existing single-datapoint rendering path already used in other SLO charts. No new API endpoint needed.

P95 Aggregated Transaction Response Time
SLO: 2 000 ms
1 850 ms
✓ Meets SLO

Pros

  • No new API endpoint
  • Clear pass/fail visual

Cons

  • No time context — single scalar only
B

Summary timeseries + threshold line

Re-use the existing /test-runs/:id/summary-timeseries endpoint to show avg response time (or error rate) over the full test duration, overlaid with the SLO threshold line. The scalar result is already shown in the table below — the chart adds the temporal context.

Avg Response Time over test run (SLO: p95 ≤ 2 000 ms)
Note: shows avg RT — not the p95 stat used for evaluation

Pros

  • Temporal context
  • No new endpoint needed

Cons

  • Shows avg RT, not the actual p95 stat
  • Slightly misleading for p50/p99 SLOs
C

New timeseries endpoint — rolling stat over time

Add a new API endpoint GET /test-runs/:id/aggregated-timeseries?metric=transaction_response_time&stat=p95 that returns the chosen percentile bucketed over the test duration. Shows exactly how the SLO metric evolved, including whether it spiked above the threshold.

P95 Response Time over time (all transactions)
Shows exact stat used for evaluation — red = above SLO threshold

Pros

  • Accurate stat, temporal context
  • Threshold breaches visible

Cons

  • Requires new API endpoint
  • More backend work
