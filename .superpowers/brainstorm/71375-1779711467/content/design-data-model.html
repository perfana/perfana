Design — Section 1: Data Model & API

Does this look right before we move on?

New DB column

test_runs table (new column)
ramp_up     INTEGER NULLABLE  ← existing (analysisStartOffset)
ramp_down   INTEGER NULLABLE DEFAULT 0  ← new (analysisEndOffset)

Semantics: 0 = no exclusion. Effective analysis window = [startTime + analysisStartOffset, endTime − analysisEndOffset]. Stored as seconds.

Shared schema / entity

  • packages/shared/src/entities/test-run.entity.ts — add @Column('ramp_down') analysisEndOffset?: number
  • packages/shared/src/schemas/index.ts — add analysisEndOffset: z.number().int().optional() to both Zod schemas
  • apps/api/src/modules/test-runs/handlers/entity-mapper.ts — map ramp_down → analysisEndOffset
  • apps/api/src/modules/test-runs/commands/create-test-run.command.ts — accept optional analysisEndOffset
  • apps/api/src/modules/test-runs/dto/update-running-test.dto.ts — add optional field
  • apps/api/src/modules/test-runs/services/test-runs-mapper.service.ts — include in mapped output

New API endpoints

PUT /test-runs/:id/analysis-time-range
Body: { analysisStartOffset: number, analysisEndOffset: number }
Handler: UpdateAnalysisTimeRangeHandler
— writes both to DB atomically
— triggers TransactionStatsRollupPipeline (one job)
— emits WebSocket UPDATED event
— audit logs both fields
GET /test-runs/:id/summary-timeseries
Returns: [{ time, throughput, avgResponseTime, errorsPerSecond }]
Source: transactions + requests_error tables
Bucket size: auto-computed from duration (reuses calculateBucketSize)
Only available when performance test data exists
(404 if no data → frontend hides button)

The old PUT .../analysis-start-offset endpoint is kept but deprecated (for any CI scripts using it directly). The frontend will no longer call it.

Database migration

New TypeORM migration: AddAnalysisEndOffsetToTestRuns — adds ramp_down INTEGER DEFAULT 0 to test_runs. Backfills existing rows to 0 (no change in behavior).
