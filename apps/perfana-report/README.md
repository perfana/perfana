# Perfana Report PDF Generation Service

> Back to [CLAUDE.md](../../CLAUDE.md) for project-wide context.

Standalone NestJS service for generating PDF reports from HTML content using Puppeteer.

## Overview

The Perfana Report service is a specialized microservice that handles resource-intensive PDF generation tasks. It consumes jobs from a BullMQ queue and uses a pool of pre-launched Puppeteer browsers for efficient PDF generation.

## Features

- **Browser Pool Management**: Pre-launched Puppeteer browsers for fast PDF generation
- **Queue-Based Processing**: Consumes PDF generation jobs from BullMQ
- **Horizontal Scaling**: Can run multiple replicas to handle high load
- **Health Checks**: Kubernetes-ready liveness and readiness probes
- **Progress Tracking**: Reports job progress for monitoring

## Configuration

- `NODE_ENV` - Environment (development/production)
- `PORT` - HTTP port (default: 3003)

- `DB_PASSWORD` - Database password

- `REDIS_PORT` - Redis port

#### Optional

- `BROWSER_POOL_SIZE` - Number of browsers in pool (default: 3)
- `PDF_TIMEOUT_MS` - PDF generation timeout in ms (default: 90000)
- `QUEUE_CONCURRENCY` - Concurrent jobs to process (default: 2)
- `LOG_LEVEL` - Logging level (default: info)

  errorCode?: string;

### Progress Stages

1. `loading_report` (10%) - Loading report from database
2. `generating_pdf` (30%) - Generating PDF from HTML
3. `storing_pdf` (80%) - Storing PDF metadata
4. `complete` (100%) - Job completed

## Browser Pool

The service maintains a pool of pre-launched Puppeteer browsers to avoid the overhead of launching a new browser for each PDF generation.

### Configuration

- **Pool Size**: Configurable via `BROWSER_POOL_SIZE` (default: 3)
- **Allocation**: Round-robin
- **Recovery**: Automatically relaunches crashed browsers

### Browser Arguments

Critical for Kubernetes deployment:
- `--no-sandbox` - Required for containerized environments
- `--disable-setuid-sandbox` - Security requirement
- `--disable-dev-shm-usage` - Prevents shared memory issues
- `--single-process` - Required for Kubernetes

## PDF Generation

### PDF Options

- **Format**: A4
- **Margins**: Top 20mm, Right/Left 15mm, Bottom 20mm
- **Print Background**: Enabled
- **Header**: Report name
- **Footer**: Page numbers and "Generated by Perfana"

### Timeout

PDF generation has a configurable timeout (default: 90 seconds) to prevent jobs from hanging indefinitely.

## Error Handling

### Retry Policy

- **Attempts**: 3
- **Backoff**: Exponential with 10s initial delay

### Error Codes

- `PDF_GENERATION_ERROR` - General PDF generation failure

## Performance

### Rate Limiting

- **Max Jobs**: 5 per minute per worker
- **Concurrency**: 2 concurrent jobs per worker
- **Lock Duration**: 2 minutes per job

### Scaling

The service can be horizontally scaled by increasing the replica count. Each replica processes jobs independently from the shared Redis queue.

## Troubleshooting

### Common Issues

#### Browser Launch Failures

**Symptom**: "Failed to launch browser" errors

**Solutions**:
1. Ensure `--no-sandbox` and `--disable-setuid-sandbox` are set
2. Check available memory (browsers require ~200-500MB each)
3. Verify Puppeteer is installed

#### Shared Memory Issues

**Symptom**: "Failed to generate PDF" with memory errors

**Solutions**:
1. Use `--disable-dev-shm-usage` flag
2. Consider mounting emptyDir with `medium: Memory` in Kubernetes

#### Queue Not Processing

**Symptom**: Jobs stuck in "waiting" state

**Solutions**:
1. Check Redis connectivity
2. Verify worker is running (check logs)
3. Check worker concurrency settings
